# ADR-0005 — Self-hosted fonts via the Astro Fonts API; CSS must consume the variables

**Status:** Accepted. Governs the PR #64 fix round.

## Context

DM Sans and DM Serif Display were loaded from the Google Fonts CDN — a render-blocking third-party stylesheet plus two preconnects, hitting mobile Core Web Vitals (mobile is where the site converts: 12.4% CTR vs 2.9% desktop) and disclosing visits to Google. PR #64 switched to the Astro Fonts API (`fonts:` in `astro.config.mjs`, google provider, downloaded at build time and served first-party).

The review caught a silent regression in the first cut: **the Fonts API registers `@font-face` under hashed family names** (`DM Sans-<hash>`), exposed only through the configured CSS variables (`--font-dm-sans`, `--font-dm-serif-display`). Stylesheets that reference the literal family name `'DM Sans'` match nothing and fall back to system fonts — while the preloaded woff2 files download unused.

## Decision

- Fonts are self-hosted via the Astro Fonts API; the `<Font cssVariable=... preload />` components in the layout are the only font loading mechanism. No `fonts.googleapis.com`/`fonts.gstatic.com` references anywhere in the build.
- **Every CSS font-family reference must consume the variables** — `var(--font-dm-sans)` / `var(--font-dm-serif-display)` — never the literal strings `'DM Sans'` / `'DM Serif Display'`. The Tailwind `@theme` tokens (`--font-sans`, `--font-serif`) map to the variables; hardcoded `font-family:` declarations in `global.css` are rewritten to use them.
- Greppable rule: a literal quoted family name in any stylesheet is a bug.

## Consequences

- **Pro:** first-party fonts, no third-party disclosure, optimized fallbacks generated by Astro (reduces layout shift).
- **Con:** build needs network access to Google once per cold cache to download font files.
- **Verification requirement:** because the failure mode is silent (perfectly valid CSS, wrong fonts), font changes must be verified by **rendered output** — computed `font-family` on a served page in a real browser — not by grepping the build for woff2 files. PR #64's original "verification" made exactly that mistake.

## Alternatives considered

- **Keep Google Fonts CDN** — rejected: render-blocking, third-party disclosure.
- **Manual @font-face with committed woff2 files** — works, but loses Astro's fallback metric generation and subsetting; more files to maintain by hand.
- **Rename generated families to literal names** — not supported by the Fonts API; fighting the tool.
